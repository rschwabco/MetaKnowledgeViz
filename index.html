🔍 Query Understanding

Extract signals — domain, temporal scope, user role, intent.

The system extracts structured signals from the raw query: what domain does this belong to? What time period matters? What role/permissions does the user have? These signals become the routing key for everything downstream.

🧠 Meta-Knowledge Layer

Make implicit applicability conditions explicit and machine-readable.

Every chunk of knowledge carries implicit properties: temporal validity (is this still current?), scope conditions (which regions/products/user-types does this cover?), and prerequisites (what must be true for this to apply?). The meta-knowledge layer makes these explicit so the system can reason about them programmatically.

🔀 Disambiguation & Routing

Route queries to the correct knowledge bases and specialized agents.

Disambiguation is the agentic layer that takes extracted signals and routes the query to the correct assistant or knowledge base — selecting which sources are in scope. This is where the architecture becomes multi-agent: the challenge shifts from understanding the query to orchestrating a response across specialized knowledge domains.

📦 Scoped Retrieval

Search within the compatibility envelope — not the entire index.

Instead of searching the full vector space, retrieval is scoped to only the knowledge bases and chunks that pass the meta-knowledge filter. This eliminates "disallowed truths" — documents that are semantically similar but don't govern the user's case — before they ever reach the LLM.

✅ Confidence & Validation

Apply authority weights and confidence thresholds before answering.

Not all documents carry equal weight. Authority depends on who created the document, in what capacity, and with what organizational standing. The validation layer applies confidence thresholds — if no retrieved chunk passes both the applicability and authority bar, the system declines to answer rather than hallucinate.
